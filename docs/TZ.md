# ТЗ: Project Z — VPN + прокси-цепочка со стабильным «домашним» IP

> Рабочее название: **Project Z** (финальное имя — позже).
> Документ — задание для агента-разработчика. Реальные ключи, подписки и пароли в репозиторий **не попадают** — только плейсхолдеры (см. §14).

---

## 1. Цель

Десктопное приложение, которое делает так, что для интернета пользователь выглядит как **обычный домашний пользователь в США** с постоянным IP, находясь в любой точке мира.

Как: весь трафик компьютера идёт по цепочке

```
Компьютер → VPN (из подписки, обход блокировок) → статический ISP-прокси США (чистый постоянный IP) → интернет
```

Ключевые требования:
1. Сайты всегда видят **только IP прокси**.
2. Отвал любого звена → **kill switch**, трафик не уходит ни напрямую, ни через «голый» IP VPN.
3. Окружение (часовой пояс, язык, DNS, WebRTC, IPv6) **согласовано** со страной IP.
4. **Выключил — компьютер ровно такой, как был до включения** (§9).
5. Честные проверки и статус (в духе проекта ClodHelper).

## 2. Платформы

| ОС | Требование |
|---|---|
| macOS | 11+, **universal** (Intel + Apple Silicon). Основное тестирование — на Intel |
| Windows | 10 / 11 x64 |

Язык интерфейса — **только русский** (строки вынести в один файл, чтобы позже добавить другие).

## 3. Стек

- **Оболочка:** Tauri 2 (Rust) + React + TypeScript + Tailwind.
- **Ядра (отдельные бинарники, поставляются с приложением):**
  - **Xray-core** — «VPN-движок»: подключается к серверам из подписки (VLESS Reality, VLESS xhttp, Hysteria, мосты, фрагментация, балансировщики). Подписка заточена именно под Xray, sing-box её целиком не поддерживает (xhttp и др.).
  - **sing-box** — TUN, маршрутизация, DNS, kill switch, пул прокси, цепочка «прокси через VPN».
  - Агенту: проверить, есть ли в актуальном Xray стабильный TUN на macOS и Windows. Если есть и закрывает все требования §6–§8 — можно упростить до одного ядра. Решение задокументировать.
- **Привилегированный помощник** (Rust): управляет ядрами, TUN, брандмауэром, системными настройками.
  - macOS: LaunchDaemon (root), ставится один раз с запросом пароля.
  - Windows: служба Windows (SYSTEM) + драйвер wintun, один запрос UAC при установке.
  - Связь UI ↔ помощник: локальный сокет / named pipe с токеном, только для текущего пользователя.
- **Лицензия:** Xray и sing-box — GPLv3 → проект open source под **GPL-3.0**.

## 4. Архитектура

```
┌──────────── UI (Tauri, без прав администратора) ────────────┐
│ подписки · прокси · статус · проверки · настройки · трей    │
└───────────────┬─────────────────────────────────────────────┘
                │ IPC (сокет/pipe + токен)
┌───────────────▼──────────── Помощник (root / SYSTEM) ───────┐
│ генерация конфигов · запуск/рестарт ядер · снимок/откат     │
│ системных настроек · брандмауэр · монитор здоровья          │
└──────┬───────────────────────────────┬──────────────────────┘
       ▼                               ▼
  sing-box (TUN)                    Xray-core
  ├ DNS, правила, kill switch       └ inbound socks 127.0.0.1:<порт>
  ├ outbound «пул прокси» ─detour─►    → балансировщик серверов подписки
  └ outbound «xray» (socks на Xray)    → VPN-серверы
```

Поток пакета: приложение → TUN → sing-box → выбранный прокси пользователя (соединение к прокси идёт **через** outbound «xray», `detour`) → Xray → VPN-сервер → прокси → сайт.

Обязательно:
- **Без петли:** трафик самого Xray к VPN-серверам не должен попадать обратно в TUN (исключение по процессу Xray и/или по IP серверов; DNS-резолв адресов VPN-серверов — напрямую, bootstrap).
- Соединение к прокси возможно **только** через Xray. Прямой маршрут к IP прокси запрещён.

## 5. Подписки

### 5.1 Формат-приоритет: Happ / Xray JSON
Пример реальной подписки (сервис EasyGo): `GET https://<домен>/subhapp/<токен>` → `Content-Type: text/json`, тело — **JSON-массив полных Xray-конфигов** (9 профилей: Германия ×N, США, «моб»).

Каждый элемент содержит: `remarks` (имя с флагом), `outbounds` (VLESS Reality / xhttp / Hysteria, `*-frag` через `dialerProxy: fragment`, `*-bridge-*`), `routing.balancers`, `burstObservatory`, `routing.rules`, `dns`, `inbounds`.

Заголовки ответа, которые надо показывать в UI:
- `Profile-Title` — имя подписки;
- `Subscription-Userinfo: expire=…; upload=…; download=…; total=…` — срок и трафик;
- `Profile-Update-Interval` — интервал автообновления (часы);
- `Profile-Web-Page-Url` — ссылка «поддержка».

Обработка:
- берём из профиля `outbounds` (кроме служебных freedom/blackhole) + `balancers` + `burstObservatory`;
- **их `routing.rules` и `dns` выбрасываем** (там «российские сайты direct», Яндекс-DNS — ломает цепочку и выдаёт страну) и генерируем свои: весь входящий трафик → балансировщик;
- `inbounds` заменяем своим socks-inbound на 127.0.0.1 (случайный свободный порт + авторизация).

### 5.2 Другие форматы (этап 2+)
- base64-список ссылок; одиночные `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`;
- Clash/mihomo YAML; sing-box JSON.
- `happ://crypt…` (шифрованные ссылки Happ) — **не поддерживаем**, показать понятную ошибку.

### 5.3 Функции
- несколько подписок; выбор профиля (страна) вручную или «авто»;
- автообновление по `Profile-Update-Interval`, кнопка «Обновить»;
- срок действия и предупреждение за 3 дня до окончания.

## 6. Прокси (финальная точка)

- **Пул**: список прокси `socks5://user:pass@host:port` и `http://user:pass@host:port`, порядок = приоритет. Ввод одной строкой, массовая вставка списком.
- **Переключение**: работаем через №1, пока он жив. Упал → следующий живой. Ожил №1 → **возвращаемся к нему** (стабильный IP важнее). Реализация: selector в sing-box + монитор помощника переключает через Clash API (urltest не подходит — он выбирает по пингу).
- **Все прокси мертвы → kill switch**, никогда не выходить через IP VPN.
- Проверка каждого прокси (через VPN): живость, пинг, выходной IP, страна, город, ASN/провайдер, тип сети, «чистота» (§10).
- Предупреждение, если резервный прокси в другой стране/штате, чем основной («при переключении сменится регион»).
- UDP: если прокси поддерживает SOCKS5 UDP — пускать UDP через него; иначе блокировать UDP для цепочки (QUIC откатится на TCP) и честно показать «звонки/видео могут не работать».

## 7. Kill switch

Три уровня:
1. **Цепочка с detour** — прокси достижим только через VPN.
2. **TUN + strict_route** — если цепочка мертва, трафик упирается в TUN.
3. **Брандмауэр** на случай падения самих ядер: macOS — `pf` (свой anchor), Windows — WFP / правила брандмауэра (своя группа). Наружу разрешено только: процессу Xray → адреса VPN-серверов; loopback; LAN (опция «разрешить локальную сеть», по умолчанию вкл. — принтеры, роутер).

| Событие | Поведение |
|---|---|
| Упал VPN-сервер | балансировщик Xray переключает сервер; на время — блок |
| Упали все серверы подписки | блок, уведомление |
| Упал прокси | следующий из пула; если нет — блок |
| Упало ядро | брандмауэр держит блок, помощник перезапускает ядро |
| Пользователь выключил | всё снимается, восстановление (§9) |

Выключить kill switch, пока цепочка не работает, — только явной кнопкой «Отключить защиту» с подтверждением.

## 8. Защита от утечек

- **DNS**: все запросы — через цепочку (fake-ip в sing-box или DoH через цепочку на американский резолвер). Системный DNS перехватывается TUN; прямые запросы к :53/:853 мимо — блок.
- **IPv6**: если цепочка не умеет — полностью блокировать IPv6 на время работы.
- **WebRTC**: в режиме TUN реальный IP не виден; дополнительно — настройка Firefox (§11).
- **QUIC/UDP**: см. §6.

## 9. Возврат к исходному состоянию (обязательно)

**Принцип: выключил приложение — компьютер такой же, как до включения.**

- Перед любым изменением помощник сохраняет **снимок** исходных значений на диск (JSON, рядом с данными помощника): часовой пояс, язык/регион, DNS и сетевые настройки, IPv6, правила брандмауэра, системный прокси, настройки Firefox.
- При выключении — восстановление **из снимка** (не «по умолчанию»): свой DNS / свой часовой пояс у пользователя вернутся именно они.
- **Аварии**: если приложение/компьютер выключились некорректно, при следующем старте — обнаружить незакрытый снимок и предложить «Восстановить сеть и настройки» (или восстановить автоматически, если цепочка не запускается).
- **Удаление программы**: деинсталлятор восстанавливает всё и удаляет правила брандмауэра, службу/LaunchDaemon, TUN.
- **Аварийная кнопка «Сбросить всё»** в настройках и в трее + отдельная команда помощника (на случай, если UI не открывается).
- В UI блок «Сейчас изменено»: список изменённого (часовой пояс → America/New_York, DNS → через туннель, …). После выключения — пусто.
- Пароль администратора — один раз при установке, не при каждом включении.

## 10. Окружение и проверки

### 10.1 Согласование окружения
По геоданным IP прокси (часовой пояс, страна):
- **часовой пояс системы** → пояс IP (macOS: `systemsetup -settimezone`, Windows: `tzutil /s`);
- **язык/регион** → en-US первым (macOS: `AppleLanguages`/`AppleLocale`, Windows: список языков пользователя + регион). Предупредить, что приложения подхватят язык после перезапуска;
- каждое изменение — опция с переключателем, по умолчанию вкл., с откатом (§9).
- Проверка согласованности на главном экране: «IP: Майами, США · часовой пояс совпадает ✅ · язык ⚠️ Исправить».

### 10.2 Проверки (вкладка «Проверки», кнопка «Проверить всё»)
| Проверка | Как |
|---|---|
| Выходной IP, страна, город, провайдер | несколько сервисов (ipinfo / ip-api / ipapi.is / cloudflare trace) через цепочку, сверить между собой |
| Чистота IP | `ip-api` (proxy/hosting/mobile), `ipapi.is` (is_datacenter/is_proxy/is_vpn/is_abuser), итог: «домашний ✅ / хостинг ⚠️ / помечен как прокси ❌». Учесть лимиты бесплатных API, кэшировать |
| Утечка DNS | DNS-leak тест через цепочку: все резолверы должны быть не российскими и не провайдера пользователя |
| IPv6 | есть ли IPv6-выход мимо цепочки |
| WebRTC | открыть локальную страницу-тест или browserleaks в браузере (из приложения это не проверить) |
| Задержки по звеньям | до VPN-сервера, до прокси (через VPN), до сайта |
| Окружение | часовой пояс и язык против страны IP |

Ни одна проверка не отправляет логины/пароли прокси и токены подписок сторонним сервисам.

## 11. Кнопка «Защитить Firefox»

- Найти профили Firefox (`profiles.ini`): macOS `~/Library/Application Support/Firefox/`, Windows `%APPDATA%\Mozilla\Firefox\`.
- Если Firefox запущен — попросить закрыть.
- Дописать в `user.js` блок между маркерами `// >>> Project Z` … `// <<< Project Z`:
  - `privacy.fingerprintingProtection = true`
  - `privacy.fingerprintingProtection.overrides` — все цели, **кроме подмены часового пояса на UTC** (точное имя цели проверить по актуальной документации Firefox; нам нужен реальный, т.е. американский, пояс);
  - `privacy.resistFingerprinting = false` (он принудительно ставит UTC — не подходит);
  - `media.peerconnection.enabled = false` (WebRTC);
  - `intl.accept_languages = "en-US, en"`, `javascript.use_us_english_locale = true`.
- Кнопка «Вернуть как было» удаляет только наш блок. Входит в общий откат (§9).
- Рекомендация в UI: для максимальной защиты отпечатка — Mullvad Browser.

## 12. Интерфейс (русский)

- **Главная**: большой переключатель; визуализация цепочки `Вы → 🇩🇪 VPN → 🇺🇸 Прокси → Интернет` с цветом каждого звена; выходной IP с флагом; статус kill switch; блок «Сейчас изменено».
- **Подписки**: список, профили/серверы, пинг, срок/трафик, обновление.
- **Прокси**: пул с порядком (drag & drop), статус, пинг, страна, чистота, кнопки «Проверить»/«Сделать основным».
- **Проверки**: §10.2.
- **Настройки**: автозапуск, запуск цепочки при старте, опции окружения, локальная сеть, Firefox, «Сбросить всё», логи (без секретов).
- **Трей**: цвет (зелёный/жёлтый/красный), вкл/выкл, текущий IP, «Сбросить всё».
- **Уведомления**: VPN упал/ожил, прокси переключён, kill switch сработал, подписка заканчивается.

## 14. Безопасность и данные

- Логины/пароли прокси и ссылки подписок хранить в **системном хранилище** (macOS Keychain, Windows Credential Manager), не в открытых файлах.
- Логи без секретов (маскировать `user:pass` и токены).
- Никакой телеметрии.
- Локальные порты (socks Xray, Clash API sing-box) — только 127.0.0.1 + авторизация/секрет.
- В репозитории — только плейсхолдеры: `socks5://USER:PASS@1.2.3.4:8000`, `https://example.com/sub/TOKEN`. Для локальных тестов — `.env.local` в `.gitignore`.
