# ТЗ: Project Z — VPN + прокси-цепочка со стабильным «домашним» IP

> Рабочее название: **Project Z** (финальное имя — позже).
> Документ — задание для агента-разработчика. Реальные ключи, подписки и пароли в репозиторий **не попадают** — только плейсхолдеры (см. §14).

---

## 1. Цель

Десктопное приложение, которое делает так, что для интернета пользователь выглядит как **обычный домашний пользователь в США** с постоянным IP, находясь в любой точке мира.

Как: весь трафик компьютера идёт по цепочке

```
Компьютер → VPN (из подписки, обход блокировок) → статический ISP-прокси США (чистый постоянный IP) → интернет
```

Ключевые требования:
1. Сайты всегда видят **только IP прокси**.
2. Отвал любого звена → **kill switch**, трафик не уходит ни напрямую, ни через «голый» IP VPN.
3. Окружение (часовой пояс, язык, DNS, WebRTC, IPv6) **согласовано** со страной IP.
4. **Выключил — компьютер ровно такой, как был до включения** (§9).
5. Честные проверки и статус (в духе проекта ClodHelper).

## 3. Стек

- **Оболочка:** Tauri 2 (Rust) + React + TypeScript + Tailwind.
- **Ядра (отдельные бинарники, поставляются с приложением):**
  - **Xray-core** — «VPN-движок»: подключается к серверам из подписки (VLESS Reality, VLESS xhttp, Hysteria, мосты, фрагментация, балансировщики). Подписка заточена именно под Xray, sing-box её целиком не поддерживает (xhttp и др.).
  - **sing-box** — TUN, маршрутизация, DNS, kill switch, пул прокси, цепочка «прокси через VPN».
  - **Почему два ядра, а не одно** (сверено с документацией, ноябрь 2026): в Xray появился TUN-inbound (Windows, Linux, macOS), но на macOS он не перехватывает системный DNS, а fake-ip и управляемого пула прокси с переключением в Xray нет. Требования §6–§8 одним Xray не закрыть. Пересматривать только при смене версий ядер.
  - **Версии ядер зафиксированы**: конкретные релизы + контрольные суммы SHA-256 в репозитории; CI и помощник проверяют суммы. Обновление версии ядра — отдельный коммит с прогоном тестов утечек (§15). Генератор конфигов пишется под зафиксированные версии, а не «под последнюю»: формат sing-box меняется от версии к версии (на ноябрь 2026 стабильная — 1.14.x; в 1.14 изменились DNS-правила, в 1.15 поле `stack` объявлено устаревшим). CI проверяет каждый сгенерированный тестовый конфиг самими ядрами: `sing-box check` и `xray run -test`.
  - **Права ядер:** Xray работает **без root/SYSTEM** — под отдельным системным пользователем (macOS: служебный пользователь `_projectz`; Windows: ограниченная учётная запись службы). Ему нужны только локальный socks-inbound и исходящие соединения. Это же даёт признак для брандмауэра (§7). sing-box — с правами, нужными для TUN.
- **Привилегированный помощник** (Rust): управляет ядрами, TUN, брандмауэром, **системными** настройками (часовой пояс). Настройки **пользователя** (язык, Firefox) меняет UI-процесс от имени пользователя, не помощник (§9).
  - macOS: LaunchDaemon (root), ставится один раз с запросом пароля администратора. Без Developer ID механизм SMJobBless недоступен, а работа SMAppService с ad-hoc подписью не гарантирована, поэтому установка — скриптом с правами администратора: помощник и ядра копируются из `.app` в каталоги root (`/Library/PrivilegedHelperTools`, `/Library/Application Support/ProjectZ`), plist — в `/Library/LaunchDaemons`. Из самого `.app` привилегированный код **не запускается**: его содержимое может менять пользователь, а при запуске из карантина путь к нему случайный. macOS 13+ показывает помощник в «Фоновых элементах» и позволяет его выключить — UI это обнаруживает и объясняет, как включить обратно.
  - Windows: служба Windows (SYSTEM) + драйвер wintun, один запрос UAC при установке.
  - Связь UI ↔ помощник: локальный сокет / named pipe. Требования к безопасности канала и API — §14.
- **Лицензия:** sing-box — GPLv3, Xray-core — MPL-2.0, wintun — собственная лицензия на готовые бинарники (распространение разрешено). Ядра запускаются отдельными процессами, поэтому лицензию нашего кода они не диктуют; проект публикуем как open source под **GPL-3.0** по собственному выбору. В дистрибутив включить тексты лицензий ядер и ссылки на их исходники.
- **Структура репозитория:** Cargo workspace с отдельными крейтами: `ipc-proto` (типы сообщений UI ↔ помощник), `config-gen` (разбор подписок и генерация конфигов ядер, чистые функции, покрыты тестами), `platform` (интерфейсы `Firewall`, `Tun`, `SystemSettings`, `ServiceManager` и их реализации для macOS и Windows — заводится на этапе 1, чтобы Windows на этапе 2 был новой реализацией, а не переписыванием), `helper` (привилегированная часть; платформенный код — только через `platform`), `app` (Tauri). Фронтенд — в `ui/`.

## 4. Архитектура

```
┌──────────── UI (Tauri, без прав администратора) ────────────┐
│ подписки · прокси · статус · проверки · настройки · трей    │
└───────────────┬─────────────────────────────────────────────┘
                │ IPC (сокет/pipe + токен)
┌───────────────▼──────────── Помощник (root / SYSTEM) ───────┐
│ генерация конфигов · запуск/рестарт ядер · снимок/откат     │
│ системных настроек · брандмауэр · монитор здоровья          │
└──────┬───────────────────────────────┬──────────────────────┘
       ▼                               ▼
  sing-box (TUN)                    Xray-core
  ├ DNS, правила, kill switch       └ inbound socks 127.0.0.1:<порт>
  ├ outbound «пул прокси» ─detour─►    → балансировщик серверов подписки
  └ outbound «xray» (socks на Xray)    → VPN-серверы
```

Поток пакета: приложение → TUN → sing-box → выбранный прокси пользователя (соединение к прокси идёт **через** outbound «xray», `detour`) → Xray → VPN-сервер → прокси → сайт.

Обязательно:
- **Без петли:** трафик самого Xray к VPN-серверам не должен попадать обратно в TUN.
  - Основной способ: все «конечные» outbound'ы Xray (те, что реально открывают соединение, включая freedom `fragment`) привязаны к физическому интерфейсу через `sockopt.interface`. Помощник следит за сменой активного интерфейса (Wi-Fi ↔ Ethernet, новая сеть) и перегенерирует привязку. По документации Xray `sockopt.interface` поддерживается на Linux, macOS и Windows; на этапе 0 подтвердить на практике.
  - Страховка: IP VPN-серверов исключены из маршрутов TUN (`route_exclude_address` в sing-box; список IP ведёт помощник, см. ниже) — пакеты к ним идут по обычному маршруту системы и в TUN не попадают. Правило sing-box «процесс Xray → direct» **не использовать**: такое соединение открыл бы сам sing-box, а брандмауэр (§7) выпускает наружу только Xray — пакет был бы заблокирован.
- **Bootstrap-DNS (резолв адресов VPN-серверов).** Системный DNS перехвачен TUN и идёт через цепочку, которой до подключения ещё нет, — получается круговая зависимость. Xray сам её не разрывает: по умолчанию (`domainStrategy: AsIs`) он резолвит адрес сервера системным DNS, то есть тем же перехваченным. Поэтому:
  - адреса VPN-серверов резолвит **помощник** — отдельным дочерним процессом-резолвером без прав root, под тем же служебным пользователем, что Xray, через физический интерфейс (DNS-серверы сети из DHCP; запасной вариант — DoH по IP);
  - в конфиг Xray подставляются **готовые IP**. Исходное доменное имя при этом явно записывается в `serverName` / `host`: если в подписке они пусты, Xray взял бы их из адреса, и после подстановки IP сломались бы TLS / Reality / xhttp. Блока `dns` в конфиге Xray нет вообще, сам Xray ничего не резолвит — имена прокси уходят на VPN-сервер как есть;
  - те же IP попадают в таблицу брандмауэра (§7) и в исключения маршрутов TUN — так правило «Xray → только адреса VPN-серверов» становится выполнимым;
  - повторный резолв: при запуске, при смене сети и когда сервер перестал отвечать (у серверов за CDN адреса меняются). Изменился набор IP → обновить таблицу брандмауэра, конфиг Xray и исключения TUN;
  - это единственный DNS-трафик мимо цепочки; брандмауэр разрешает его только резолверу и только к DNS-серверам сети (§7). Резолвятся только домены серверов подписки; результаты кэшируются.
- Соединение к прокси возможно **только** через Xray. Прямой маршрут к IP прокси запрещён.

### 4.1 Машина состояний

Помощник — единственный владелец состояния; UI только отображает его и шлёт команды.

```
Выключено → Запуск → Защищено ⇄ Блок (цепочка не работает, kill switch держит)
                ↘ ошибка → Откат → Выключено
Защищено / Блок → Остановка → Откат → Выключено
```

- Каждый переход журналируется; порядок запуска: снимок → брандмауэр → Xray → проверка VPN → sing-box/TUN → проверка прокси → «Защищено». Остановка — в обратном порядке, брандмауэр снимается последним.
- Брандмауэр ставится **до** запуска ядер и снимается **после** их остановки — нет окна, когда TUN уже/ещё нет, а трафик разрешён.
- События сети (сон/пробуждение, смена Wi-Fi, смена интерфейса) → состояние «Блок» → перепривязка интерфейса → перепроверка цепочки → «Защищено».
- Конфликты: если обнаружен другой активный VPN/TUN или iCloud Private Relay — предупредить до запуска.
- **Состояние переживает сбой помощника.** Желаемое состояние (вкл/выкл, профиль, прокси) и текущий шаг перехода пишутся на диск атомарно. При каждом своём старте (после падения, обновления, перезагрузки) помощник сверяет записанное с фактическим — процессы ядер, TUN, правила брандмауэра, снимок — и доводит систему до желаемого состояния либо выполняет откат. «Полузапущенных» состояний после старта не остаётся.
- **Сторож правил.** Монитор здоровья регулярно проверяет, что свои правила брандмауэра на месте (система или другая программа может перезагрузить набор правил `pf`). Пропали при активной цепочке → восстановить и записать в журнал.
- «Вход в Wi-Fi» (§7) — отдельное состояние, ограниченное по времени; выход из него — только в «Блок» с перепроверкой цепочки.

## 5. Подписки

### 5.1 Формат-приоритет: Happ / Xray JSON
Пример реальной подписки (сервис EasyGo): `GET https://<домен>/subhapp/<токен>` → `Content-Type: text/json`, тело — **JSON-массив полных Xray-конфигов** (9 профилей: Германия ×N, США, «моб»).

Каждый элемент содержит: `remarks` (имя с флагом), `outbounds` (VLESS Reality / xhttp / Hysteria, `*-frag` через `dialerProxy: fragment`, `*-bridge-*`), `routing.balancers`, `burstObservatory`, `routing.rules`, `dns`, `inbounds`.

Заголовки ответа, которые надо показывать в UI:
- `Profile-Title` — имя подписки;
- `Subscription-Userinfo: expire=…; upload=…; download=…; total=…` — срок и трафик;
- `Profile-Update-Interval` — интервал автообновления (часы);
- `Profile-Web-Page-Url` — ссылка «поддержка».

Обработка:
- берём `balancers` + `burstObservatory` и те `outbounds`, на которые они ссылаются, **вместе со всеми зависимостями по цепочке ссылок** (`dialerProxy`, `proxySettings`). Важно: freedom-outbound `fragment` — не «служебный», на него ссылаются `*-frag`; его нужно оставить. Всё, на что никто не ссылается (direct/block и т.п.), выбрасываем;
- **их `routing.rules` и `dns` выбрасываем** (там «российские сайты direct», Яндекс-DNS — ломает цепочку и выдаёт страну) и генерируем свои: весь входящий трафик → балансировщик; блока `dns` нет, адреса серверов заранее заменены на IP (§4);
- `inbounds` заменяем своим socks-inbound на 127.0.0.1 (случайный свободный порт + авторизация, UDP включён);
- **подписка — недоверенный ввод.** Конфиг не передаётся в Xray «как есть»: разбираем в свои типы и собираем заново. Белый список протоколов (vless, vmess, trojan, shadowsocks, hysteria, freedom только как цель `dialerProxy`) и полей; неизвестные протоколы и поля — отбрасываем с записью в лог; пути к файлам, `loopback`, `dns`-outbound, произвольные `inbounds`, `api`, `policy` из подписки не принимаем. Профиль, который не прошёл проверку, показывается как «не поддерживается», остальные работают.

Загрузка подписки:
- заголовки запроса как у клиента Happ (`User-Agent` и др.) — многие сервисы отдают Xray-JSON только ему. Агенту: проверить на реальной подписке, какие заголовки обязательны (в т.ч. идентификатор устройства), и вынести их в настройки подписки;
- цепочка **выключена** → запрос напрямую; цепочка **включена** → запрос через Xray (VPN), **не** через прокси и не напрямую; при «Блок» — обновление откладывается;
- ответ ограничен по размеру и времени; при ошибке обновления работает последняя удачная копия;
- подписку скачивает и разбирает помощник, но **не под root**: в дочернем процессе под служебным пользователем, наружу отдаётся только результат в типах `ipc-proto`. Адрес — только `https://`; перенаправления — только на `https://` и не на локальные/частные адреса; проверка сертификата не отключается.

### 5.2 Другие форматы (этап 2+)
- base64-список ссылок; одиночные `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://`;
- Clash/mihomo YAML; sing-box JSON.
- `happ://crypt…` (шифрованные ссылки Happ) — **не поддерживаем**, показать понятную ошибку.

### 5.3 Функции
- несколько подписок; выбор профиля (страна) вручную или «авто»;

- срок действия и предупреждение за 3 дня до окончания.

## 6. Прокси (финальная точка)

- **Пул**: список прокси `socks5://user:pass@host:port` и `http://user:pass@host:port`, порядок = приоритет. Ввод одной строкой, массовая вставка списком.
- **Режим пула** (настройка):
  - **«Только основной»** (по умолчанию): работаем только через №1; упал → блок и уведомление, IP не меняется никогда;
  - **«С резервом»**: упал №1 → следующий живой; ожил №1 → **возвращаемся к нему**.
- **Переключение** (режим «С резервом»). Реализация: selector в sing-box (`interrupt_exist_connections: true`) + монитор помощника переключает через Clash API (urltest не подходит — он выбирает по пингу).
  - **Порядок проверки: сначала VPN, потом прокси.** Если VPN не работает, прокси не считаются мёртвыми и переключения нет — иначе падение VPN выглядит как «все прокси упали».
  - Прокси считается упавшим после N неудач подряд (по умолчанию 3), а не по одной.
  - Возврат к основному — только после устойчивого восстановления (по умолчанию 5 успешных проверок подряд за ≥2 минуты), чтобы IP не скакал.
  - Каждое переключение — уведомление с новым IP.
- **Все прокси мертвы → kill switch**, никогда не выходить через IP VPN.
- Проверка каждого прокси (через VPN): живость, пинг, выходной IP, страна, город, ASN/провайдер, тип сети, «чистота» (§10).
- Предупреждение, если резервный прокси в другой стране/штате, чем основной («при переключении сменится регион»).
- UDP: если прокси поддерживает SOCKS5 UDP — пускать UDP через него; иначе блокировать UDP для цепочки (QUIC откатится на TCP) и честно показать «звонки/видео могут не работать».

## 7. Kill switch

Три уровня:
1. **Цепочка с detour** — прокси достижим только через VPN.
2. **TUN + strict_route** — если цепочка мертва, трафик упирается в TUN. Внимание: `strict_route` реально работает на Windows; на macOS он почти ничего не даёт, и при падении sing-box TUN с маршрутами исчезает. Поэтому уровень 2 сам по себе не защита, и уровень 3 обязателен **с первого этапа**.
3. **Брандмауэр** — основная защита, работает независимо от ядер. Ставится до запуска ядер, снимается после остановки (§4.1).
   - **macOS — `pf`**, свой anchor. `pf` не умеет фильтровать по процессу, только по пользователю: разрешение выдаётся **пользователю, под которым работает Xray** (`user _projectz`). Anchor подключать так, чтобы не править `/etc/pf.conf` пользователя (агенту: проверить вариант с anchor внутри `com.apple/*`); `pf` включать через `pfctl -E` и хранить токен, выключать через `pfctl -X <токен>` — не ломаем чужое использование `pf`.
   - **Windows — WFP напрямую** (свой provider и sublayer), фильтры по пути приложения Xray и резолвера помощника (§4). Не правила штатного брандмауэра: их может изменить пользователь/другая программа, и запрещающие правила там конфликтуют с разрешающими. Фильтры создаются **вне динамической сессии** — обычные, не привязанные к процессу службы: они переживают её падение и исчезают при перезагрузке. Постоянные (persistent) и boot-time фильтры ставятся **только** при включённом «запуске цепочки при старте» (см. ниже). Иначе после аварии или неудачного удаления программы компьютер остался бы без интернета до ручной чистки.
   - Наружу через физический интерфейс разрешено только: Xray → IP VPN-серверов из таблицы, которую ведёт помощник (§4); резолвер помощника → DNS-серверы сети (bootstrap-DNS, §4); DHCP; loopback; LAN (опция «разрешить локальную сеть», по умолчанию вкл. — принтеры, роутер; DNS на адреса LAN при этом **всё равно блокируется**). Через TUN — разрешено всё.
   - **Загрузка системы.** Если включён «запуск цепочки при старте», правила брандмауэра загружаются при старте системы до входа пользователя (LaunchDaemon / boot-time фильтры WFP) — чтобы не было окна с прямым трафиком. Если опция выключена — после перезагрузки компьютер в обычном состоянии.
   - **Wi-Fi с порталом авторизации** (отели, аэропорты). Открыть на время прямой доступ всем приложениям нельзя: фоновые программы и открытые вкладки браузера сразу покажут сайтам настоящий IP (нарушение требования №1 из §1), а `pf` не умеет разрешать по процессу. Поэтому кнопка «Войти в сеть Wi-Fi» работает так:
     - основной вариант: портал открывается во **встроенном окне приложения** (отдельное хранилище cookie), а его трафик идёт через локальный «портальный» прокси, который помощник запускает под отдельным служебным пользователем. Брандмауэр на время (до 5 минут, таймер на экране) выпускает наружу только этот прокси: TCP 80/443 и DNS к серверам сети. Все остальные приложения остаются заблокированными. Агенту: проверить настройку прокси для webview в Tauri на обеих ОС (на macOS она, по документации, доступна начиная с macOS 14);
     - запасной вариант (где основной недоступен, в т.ч. macOS 13): на то же время разрешить всем только TCP 80/443 и DNS к серверам сети, с явным предупреждением «на это время сайты увидят ваш настоящий IP — закройте браузеры и другие программы». В журнале и в тесте утечек это окно помечается как преднамеренное;
     - по таймеру или после успешной проверки выхода в интернет блок возвращается автоматически.

| Событие | Поведение |
|---|---|
| Упал VPN-сервер | балансировщик Xray переключает сервер; на время — блок |
| Упали все серверы подписки | блок, уведомление |
| Упал прокси | режим «Только основной» — блок; «С резервом» — следующий из пула, если нет — блок (§6) |
| Сменилась сеть / пробуждение | блок на время перепривязки и перепроверки цепочки (§4.1) |
| Упало ядро | брандмауэр держит блок, помощник перезапускает ядро |
| Пользователь выключил | всё снимается, восстановление (§9) |

Выключить kill switch, пока цепочка не работает, — только явной кнопкой «Отключить защиту» с подтверждением.

## 8. Защита от утечек

- **DNS**: все запросы — через цепочку. Основной вариант — fake-ip в sing-box + передача доменного имени прокси (резолвит сам прокси — DNS совпадает с провайдером IP); запасной — DoH через цепочку на американский резолвер. Системный DNS **не меняем** — он перехватывается TUN (`hijack-dns`); прямые запросы к :53/:853 мимо — блок. Единственное исключение — bootstrap-DNS помощника (§4).
- **IPv6**: системные настройки IPv6 **не трогаем**. TUN получает IPv6-адрес и забирает весь IPv6-трафик; если цепочка IPv6 не умеет — sing-box его отклоняет (приложения откатываются на IPv4), а брандмауэр блокирует IPv6 на физическом интерфейсе.
- **WebRTC**: в режиме TUN реальный внешний IP не виден; дополнительно — настройка Firefox (§11).
- **Геолокация**: системные службы геолокации определяют место по Wi-Fi и выдают реальное положение сайтам, которым пользователь разрешил доступ. Показать предупреждение в проверке «Окружение»; сами службы не отключаем.
- **QUIC/UDP**: см. §6.

## 9. Возврат к исходному состоянию (обязательно)

**Принцип: выключил приложение — компьютер такой же, как до включения.**

- **Меняем как можно меньше.** Системный DNS, системный прокси и настройки IPv6 **не изменяются вообще** — всё делается перехватом в TUN и своими правилами брандмауэра (§7, §8). Чем меньше изменено, тем меньше откатывать. Полный список того, что приложение вправе менять: свои правила брандмауэра (anchor / WFP-sublayer), TUN-интерфейс и его маршруты, часовой пояс и флаг «пояс автоматически», язык/регион пользователя, свой блок в настройках Firefox. Любое новое изменение системы добавляется в этот список и в снимок.
- Перед каждым изменением сохраняется **снимок** исходного значения (JSON). Запись — **до** изменения и атомарно (временный файл → fsync → переименование), чтобы сбой в любой момент оставлял годный снимок.
- **Два снимка по уровню прав:** системный (часовой пояс, брандмауэр, TUN) ведёт помощник; пользовательский (язык/регион, Firefox) ведёт UI-процесс от имени пользователя. Помощник не пишет в домашнюю папку пользователя — иначе файлы станут принадлежать root.
- При выключении — восстановление **из снимка** (не «по умолчанию»): свой часовой пояс у пользователя вернётся именно он.
- **Не затираем изменения пользователя:** значение восстанавливается, только если сейчас оно равно тому, что установили мы. Если пользователь сам поменял его во время работы — оставляем как есть и сообщаем об этом.
- Свои правила брандмауэра и TUN не «восстанавливаются», а **удаляются** целиком (свой anchor / sublayer) — чужие правила не затрагиваются.
- **Кэш DNS.** При fake-ip (§8) в кэше системы остаются фиктивные адреса, и после выключения сайты какое-то время не открываются. При остановке, после снятия TUN, помощник сбрасывает кэш DNS системы (macOS: `dscacheutil -flushcache` и `killall -HUP mDNSResponder`; Windows: `ipconfig /flushdns`).
- **Аварии**: помощник при каждом своём старте сверяет состояние (§4.1). Упал только помощник → он поднимается и продолжает держать желаемое состояние. Компьютер перезагрузился посреди работы, а «запуск цепочки при старте» выключен → правила брандмауэра и TUN уже исчезли сами (§7); остаётся незакрытый снимок настроек — предложить «Восстановить настройки» (или восстановить автоматически, если цепочка не запускается).
- **Удаление программы**: деинсталлятор восстанавливает всё и удаляет правила брандмауэра, службу/LaunchDaemon, TUN.
- **Аварийная кнопка «Сбросить всё»** в настройках и в трее + отдельная команда помощника (на случай, если UI не открывается).
- В UI блок «Сейчас изменено»: список изменённого (часовой пояс → America/New_York, брандмауэр → правила Project Z, язык → en-US, …). После выключения — пусто.
- Пароль администратора — один раз при установке, не при каждом включении.

## 10. Окружение и проверки

### 10.1 Согласование окружения
По геоданным IP прокси (часовой пояс, страна):
- **часовой пояс системы** → пояс IP (macOS: `systemsetup -settimezone`, Windows: `tzutil /s`). Перед этим запомнить и выключить «устанавливать пояс автоматически» (macOS — по геопозиции, Windows — служба автопояса), иначе система вернёт пояс сама; при откате вернуть и флаг. Для Windows нужна таблица соответствия IANA → имена поясов Windows (CLDR `windowsZones`);
- **язык/регион** → en-US первым (macOS: `AppleLanguages`/`AppleLocale`, Windows: список языков пользователя + регион). en-US **добавляется** первым в существующий список — остальные языки и раскладки клавиатуры сохраняются (на Windows замена списка целиком удаляет раскладки). Меняет UI-процесс от имени пользователя (§9). Предупредить, что приложения подхватят язык после перезапуска и что действует это не на все браузеры (Chrome на Windows берёт языки из собственных настроек) — показать в проверке «Окружение»;
- каждое изменение — опция с переключателем и откатом (§9). По умолчанию: часовой пояс — вкл., язык/регион — **выкл.** (самое заметное для пользователя изменение).
- Проверка согласованности на главном экране: «IP: Майами, США · часовой пояс совпадает ✅ · язык ⚠️ Исправить».

### 10.2 Проверки (вкладка «Проверки», кнопка «Проверить всё»)
| Проверка | Как |
|---|---|
| Выходной IP, страна, город, провайдер | несколько сервисов (ipinfo / ip-api / ipapi.is / cloudflare trace) через цепочку, сверить между собой |
| Чистота IP | `ip-api` (proxy/hosting/mobile), `ipapi.is` (is_datacenter/is_proxy/is_vpn/is_abuser), итог: «домашний ✅ / хостинг ⚠️ / помечен как прокси ❌». Учесть лимиты бесплатных API, кэшировать. Бесплатный `ip-api` работает только по HTTP и только для некоммерческого использования — учитывать при выборе сервисов |
| Утечка DNS | DNS-leak тест через цепочку (сервис с API; агенту: выбрать и зафиксировать): все резолверы должны быть не российскими и не провайдера пользователя |
| Утечка мимо туннеля | помощник кратко слушает физический интерфейс: исходящие пакеты допустимы только к VPN-серверам, bootstrap-DNS, DHCP и LAN |
| IPv6 | есть ли IPv6-выход мимо цепочки |
| WebRTC | открыть локальную страницу-тест или browserleaks в браузере (из приложения это не проверить) |
| Задержки по звеньям | до VPN-сервера, до прокси (через VPN), до сайта |
| Окружение | часовой пояс и язык против страны IP |

Ни одна проверка не отправляет логины/пароли прокси и токены подписок сторонним сервисам.

## 11. Кнопка «Защитить Firefox»

- Найти профили Firefox (`profiles.ini`): macOS `~/Library/Application Support/Firefox/`, Windows `%APPDATA%\Mozilla\Firefox\`.
- Если Firefox запущен — попросить закрыть.
- Дописать в `user.js` блок между маркерами `// >>> Project Z` … `// <<< Project Z`:
  - `privacy.fingerprintingProtection = true`
  - `privacy.fingerprintingProtection.overrides` — все цели, **кроме подмены часового пояса на UTC** (точное имя цели проверить по актуальной документации Firefox; нам нужен реальный, т.е. американский, пояс);
  - `privacy.resistFingerprinting = false` (он принудительно ставит UTC — не подходит);
  - WebRTC — два варианта на выбор: **«мягкий»** (по умолчанию): `media.peerconnection.ice.default_address_only = true`, `media.peerconnection.ice.no_host = true` — звонки работают, локальные адреса скрыты; **«строгий»**: `media.peerconnection.enabled = false` — WebRTC выключен полностью (ломает звонки и сам по себе заметен сайтам);
  - `intl.accept_languages = "en-US, en"`. Агенту: проверить по актуальной документации, какая настройка задаёт английскую локаль JS без `resistFingerprinting` (`javascript.use_us_english_locale` / `privacy.spoof_english` могут работать только вместе с ним).
- Изменения делает UI-процесс от имени пользователя (§9).
- **Откат.** Firefox копирует значения из `user.js` в `prefs.js`, поэтому простое удаление нашего блока ничего не возвращает. Перед изменением — сохранить в снимок исходное значение каждой настройки из `prefs.js` (или факт её отсутствия). «Вернуть как было» (при закрытом Firefox): удалить наш блок из `user.js` и в `prefs.js` вернуть исходные значения / удалить строки, которых не было. Только для настроек, значение которых всё ещё наше. Входит в общий откат (§9).
- Рекомендация в UI: для максимальной защиты отпечатка — Mullvad Browser.

## 12. Интерфейс (русский)

- **Главная**: большой переключатель; визуализация цепочки `Вы → 🇩🇪 VPN → 🇺🇸 Прокси → Интернет` с цветом каждого звена; выходной IP с флагом; статус kill switch; блок «Сейчас изменено».
- **Подписки**: список, профили/серверы, пинг, срок/трафик, обновление.
- **Прокси**: пул с порядком (drag & drop), статус, пинг, страна, чистота, кнопки «Проверить»/«Сделать основным».
- **Проверки**: §10.2.
- **Настройки**: автозапуск, запуск цепочки при старте, режим пула прокси, опции окружения, локальная сеть, «Войти в сеть Wi-Fi», Firefox, «Сбросить всё», логи (без секретов).
- **Трей**: цвет (зелёный/жёлтый/красный), вкл/выкл, текущий IP, «Сбросить всё».
- **Уведомления**: VPN упал/ожил, прокси переключён, kill switch сработал, подписка заканчивается.

## 13. Распространение

- GitHub Releases: macOS `.dmg` (universal), Windows `.exe` (NSIS).
- CI на GitHub Actions: сборка обеих платформ, universal-бинарники ядер (lipo), прогон тестов.
- Автообновление: Tauri updater с подписью релизов.
  - Помощник и ядра обновляются вместе с приложением: новый помощник ставится только после проверки подписи пакета обновления **самим помощником** (ключ зашит в него), без повторного запроса пароля. Версии UI и помощника сверяются при подключении; при несовпадении — обновление помощника или понятная ошибка.
  - Windows: штатный Tauri updater запускает NSIS-установщик, а установка в Program Files — это запрос UAC при каждом обновлении. Чтобы обойтись без него, пакет скачивает UI, а проверяет подпись и устанавливает служба-помощник (SYSTEM). Агенту: подтвердить на этапе 6; если не получается — допустим один запрос UAC на обновление, решение записать в `docs/`.
  - Обновление не выполняется при работающей цепочке: сначала штатная остановка с откатом.
- Без платных сертификатов: в README — инструкции обхода Gatekeeper/SmartScreen (на macOS 15+ запуск через «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть»). На Apple Silicon бинарники обязаны иметь хотя бы ad-hoc подпись. Возможны ложные срабатывания антивирусов на ядра — описать в README. Нотаризация — позже.

## 14. Безопасность и данные

- **Секреты хранит только помощник.** Логины/пароли прокси и ссылки подписок лежат в каталоге данных помощника (доступ только root/SYSTEM; на Windows дополнительно шифрование DPAPI уровня машины). Связка ключей пользователя (Keychain / Credential Manager) не подходит: помощник под root её не читает, а при «запуске цепочки при старте» пользователь ещё не вошёл. UI секреты не хранит: передаёт их помощнику один раз при вводе и дальше показывает только в скрытом виде. Конфиги ядер с секретами доступны только помощнику и пользователю соответствующего ядра (или передаются ядру через stdin).
- Логи без секретов (маскировать `user:pass` и токены).
- Никакой телеметрии.
- Локальные порты (socks Xray, Clash API sing-box) — только 127.0.0.1 + авторизация/секрет.
- **Помощник — граница привилегий.** Всё, что приходит от UI, считается недоверенным:
  - канал: сокет/pipe доступен только пользователю, установившему приложение (права на сокет / ACL по SID); помощник дополнительно проверяет uid/SID подключившегося. Токен — дополнение, а не единственная защита;
  - API узкий и типизированный (`ipc-proto`): команды вида «включить», «выключить», «задать список прокси», «задать подписку». Помощник **не принимает** от UI готовые конфиги ядер, пути к файлам, имена бинарников и команды оболочки;
  - конфиги ядер генерирует сам помощник из проверенных данных; ядра запускаются только из каталога, доступного на запись лишь root/SYSTEM, с проверкой контрольных сумм;
  - каталог данных помощника (снимок, конфиги с секретами) недоступен другим пользователям.
- В репозитории — только плейсхолдеры: `socks5://USER:PASS@1.2.3.4:8000`, `https://example.com/sub/TOKEN`. Для локальных тестов — `.env.local` в `.gitignore`.

| **Позже** | выборочный режим (только выбранные приложения/сайты через цепочку, остальное — напрямую или через VPN) | — |

**Тест утечек (обязательный критерий, начиная с этапа 1).** Проверка «нет интернета» недостаточна. Скрипт записывает пакеты на физическом интерфейсе (`tcpdump` / `pktmon`) и проверяет, что исходящие пакеты идут **только** на адреса VPN-серверов, bootstrap-DNS, DHCP и (если разрешено) LAN. Сценарии: обычная работа; убит Xray; убит sing-box; убит помощник; отключён прокси; отключён VPN-сервер; смена сети; сон/пробуждение; включение и выключение цепочки. Любой посторонний пакет — тест не пройден. Скрипт лежит в репозитории и запускается перед каждым релизом и при смене версии ядра.

**Модульные тесты** (`config-gen`): разбор подписки (включая `*-frag`, `*-bridge-*`, мусорные и вредоносные поля), генерация конфигов, откат снимка (включая «пользователь изменил значение сам»).
